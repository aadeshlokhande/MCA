## 🔹 Core Idea (Simple Language)

Tum ek aisa platform banaoge jaha **ready-made political website templates** honge.
Politician signup karega → apni details dalega → website auto-generate ho jayegi.

Example:
`nitin-gadkari.apnaneta.com`

Isse:

* Tumhe har client ke liye alag website manually banani nahi padegi
* Ek scalable business banega

# 🔹 MVP Django Architecture

MVP me zyada apps banane ki zarurat nahi hai.
Simple rakho but modular.

## ✅ Recommended Apps (MVP)

Total: **5 apps**

1. accounts
2. leaders
3. websites
4. templates
5. adminpanel (optional but useful)

---

# 🔹 1. accounts App

Authentication + restricted access

## Purpose

* Politician login only
* No public signup

## Models

### User (Custom User Model)

Use custom user from start.

Fields:

* id
* full_name
* email (login)
* phone
* password
* is_verified
* is_active
* role (politician, admin)
* created_at

👉 Use AbstractUser or AbstractBaseUser

---

# 🔹 2. leaders App

Politician profile data

## Purpose

Website content yaha se generate hoga.

## Models

### LeaderProfile

Fields:

* user (FK)
* slug (nitin-gadkari)
* party_name
* constituency
* designation
* bio
* profile_photo
* cover_image
* is_published

---

### Achievement

* leader (FK)
* title
* description
* year

---

### SocialLink

* leader (FK)
* platform (facebook, twitter)
* url

---

# 🔹 3. websites App

Public website generation logic

## Purpose

Subdomain + visibility control

## Models

### Website

* leader (OneToOne)
* subdomain (nitin-gadkari)
* is_live
* created_at
* theme (FK template)

---

### PageVisit (optional analytics)

* website
* ip_address
* visited_at

(MVP me skip bhi kar sakte ho)

---

# 🔹 4. templates App

Pre-built designs

## Purpose

Multiple themes support

## Models

### Template

* name
* preview_image
* theme_code (template folder name)
* is_active

---

# 🔹 5. adminpanel App (Optional but Smart)

Internal control panel

## Purpose

* Approve politicians
* Block misuse
* Manage templates

## Models

### SignupRequest (if invite flow)

* name
* phone
* email
* status (pending, approved, rejected)

---

# 🔹 Relationships (Important)

User → LeaderProfile (1-1)
LeaderProfile → Website (1-1)
LeaderProfile → Achievements (1-M)
LeaderProfile → SocialLinks (1-M)
Website → Template (M-1)

---

# 🔹 Subdomain System (MVP Logic)

Example:
`nitin-gadkari.apnaneta.com`

Flow:

1. Leader slug save karo
2. Subdomain = slug
3. Middleware detect kare subdomain
4. Website render based on slug
