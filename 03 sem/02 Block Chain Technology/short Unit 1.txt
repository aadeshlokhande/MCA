A. Blockchain Fundamentals
1. Public Ledgers
Public ledger ko ek open register ki tarah samjho, jise koi bhi dekh sakta hai. Isme hone wali transactions sabke saamne record hoti hain. Traditional bank ledger sirf bank maintain karta hai, lekin public ledger multiple people ke paas available hota hai.
Analogy: Society ka notice board, jahan expenses sab residents dekh sakte hain.
Example: Bitcoin transactions publicly verify ki ja sakti hain.

2. Blockchain as a Public Ledger
Blockchain ek digital register ki tarah hai jisme transactions permanently record hoti hain. Is register ki copies network ke bahut saare computers par hoti hain. Koi single person isko control nahi karta.
Analogy: Ek common diary jiska photocopy har member ke paas hai. Agar koi ek copy change kare, baaki copies mismatch dikha dengi.
Example: Bitcoin payments blockchain mein record hote hain.

3. Bitcoin and Blockchain
Bitcoin ek digital currency hai, jabki Blockchain woh technology hai jo Bitcoin ke transactions ko record aur secure karti hai. Matlab Bitcoin ko product aur Blockchain ko uske supporting system ki tarah samajh sakte ho.
Analogy: Email ek service hai aur Internet usko chalane wali technology.
Example: Jab Bitcoin send hota hai, transaction Blockchain par record hoti hai.

4. Blockchain 2.0
Blockchain 2.0 ka matlab hai blockchain ka use sirf cryptocurrency tak limited na rehkar smart contracts aur applications ke liye karna. Ismein blockchain ek programmable platform ban gaya.
Analogy: Pehle mobile sirf calling ke liye tha, baad mein smartphones mein apps aa gayi.
Example: Ethereum par smart contracts aur decentralized applications banaye ja sakte hain.

5. Smart Contracts
Smart contract ek automatic digital agreement hai. Ismein rules pehle se code mein likhe hote hain. Jab required condition satisfy hoti hai, contract automatically action perform karta hai. Human middleman ki requirement kam ho jaati hai.
Analogy: Vending machine mein paise daalo → machine automatically drink de deti hai.
Example: Payment receive hote hi digital asset automatically transfer ho sakta hai.

6. Block in a Blockchain
Block blockchain ka ek digital container hai jisme multiple transactions store hoti hain. Ismein transactions ke saath timestamp aur previous block ka hash bhi hota hai. Har block previous block se connected hota hai.
Analogy: Ek notebook ke pages ki tarah—har page previous page se connected hai.
Example: Bitcoin ki multiple transactions ek block mein store hoti hain.

7. Blockchain Transactions
Blockchain transaction ka matlab hai blockchain par koi value ya information transfer karna. Transaction network par send hoti hai, nodes usko check karte hain aur valid hone par block mein add kar dete hain.
Analogy: Courier bhejne se pehle address verify hota hai, phir parcel delivery record mein add hota hai.
Example: Aap kisi ko Bitcoin send karte ho.

8. Distributed Consensus
Distributed consensus ka matlab hai network ke multiple computers ka ek decision par agree karna. Koi single boss decision nahi leta. Network ke rules ke according nodes decide karte hain ki transaction valid hai ya nahi.
Analogy: Friends trip plan kar rahe hain aur sab voting karke ek destination decide karte hain.
Example: Bitcoin mein Proof of Work consensus mechanism use hota hai.

9. Blockchain Chain and Longest Chain
Blockchain mein blocks ek ke baad ek connected hote hain, bilkul chain ke links ki tarah. Kabhi network mein temporary two chains ban sakti hain. Bitcoin mein generally longest valid chain ko accepted chain maana jata hai.
Analogy: Do railway tracks temporarily ban gaye; system eventually longer valid route ko follow karta hai.
Example: 5 valid blocks wali chain 4 blocks wali chain par prefer ki ja sakti hai.

10. Evolution from Cryptocurrency to Blockchain 2.0
Initially blockchain ka main purpose cryptocurrency transfer tha. Bitcoin ne ye concept popular kiya. Baad mein blockchain ka use smart contracts, digital assets aur applications ke liye hone laga. Isi development ko Blockchain 2.0 kaha gaya.
Analogy: Calculator pehle sirf calculations karta tha, baad mein computers ne multiple tasks perform karna start kiya.
Example: Bitcoin → cryptocurrency, Ethereum → smart contracts.

11. Permissioned Blockchain Model
Permissioned blockchain mein har koi freely network join nahi kar sakta. Sirf authorized people ya organizations ko access diya jata hai. Ye businesses ke liye useful hai jahan privacy aur control important hain.
Analogy: Office building mein koi bhi enter nahi kar sakta; sirf employees ke paas access card hota hai.
Example: Banks apne internal transactions ke liye permissioned blockchain use kar sakte hain.

B. Cryptographic Foundations
1. Cryptographic Hash Functions
Hash function kisi bhi data ko ek fixed-size code, yani hash, mein convert karta hai. Same data ka same hash aata hai, lekin data mein chhota change hone par hash completely change ho sakta hai. Original data ko hash se easily recover nahi kiya ja sakta.
Analogy: Fingerprint ki tarah—person ko identify karne ke liye unique pattern.
Example: `"Hello"` aur `"hello"` ke hashes different honge.

2. Properties of Hash Functions
Good cryptographic hash function ki kuch important properties hoti hain: same input → same output, fixed-size output, fast calculation, preimage resistance, collision resistance aur avalanche effect. In properties ki wajah se data ko securely verify kiya ja sakta hai.
Analogy: Ek perfect fingerprint system jahan tiny change bhi different fingerprint create kare.
Example: `"Hello"` mein ek letter change karne par completely different hash milta hai.

3. Hash Pointers
Hash pointer ek normal pointer ki tarah kisi data ko point karta hai, lekin saath mein us data ka hash bhi store karta hai. Isse pata chal sakta hai ki data mein koi change hua hai ya nahi.
Analogy: Parcel ka address + parcel ki unique ID dono store karna.
Example: Blockchain ka current block previous block ka hash store karta hai, jisse previous block verify hota hai.

4. Merkle Trees
Merkle Tree transactions ko efficiently verify karne ka tree-like structure hai. Pehle individual transactions ke hashes bante hain, phir un hashes ko pair mein combine kiya jata hai. Ye process repeat hota hai jab tak ek final hash nahi milta, jise Merkle Root kehte hain.
Analogy: School mein students → classes → department → ek final school record.
Example: 4 transactions ke hashes combine hokar ek single Merkle Root banate hain.
